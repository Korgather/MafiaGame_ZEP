# FTUE 및 플레이어 여정 구현 결과

## 반영 내용과 기대 효과

| 변경 | 기대 효과 |
| --- | --- |
| 로비 접속자 수와 짧은 여정 설명 | 방을 고르기 전 게임의 목적과 활성도를 즉시 이해 |
| 로비/관전 게임 방법 버튼과 4단계 안내 | 긴 규칙을 외우지 않고 필요한 순간 다시 확인 |
| 관전 단계 안내 및 종료 버튼 | 사망/대기 중에도 현재 상황과 다음 행동을 잃지 않음 |
| 게스트 관전 전용 정책과 익명 이름 강제 | 로그인 경계가 명확하고 닉네임을 통한 우회 참가 방지 |
| 시작 시 공격 잠금과 방 중심 카메라 | 직업 공개와 토론에 시선을 집중하고 오조작 방지 |
| 종료/중단/재접속 복구 | 공격·카메라 상태가 다음 플레이까지 남는 회귀 방지 |
| 유령 채팅 역할 비공개 | 사망자끼리도 추리의 비밀을 유지 |
| 번호 + 원래 닉네임 정체 공개 | 판 중 익명 참가자를 실제 플레이어와 쉽게 연결 |
| 개인 복기 | 결과를 승패 한 줄이 아니라 자신의 선택과 연결 |
| 한 판 더 현황 + 두 번째 판 계측 | 결과 화면에서 반복 플레이로 자연스럽게 이동 |
| 결과 화면 이탈/재접속 현황 보정 | 승패 후 이탈을 중도 이탈로 오기록하지 않고 대기 인원을 정확히 표시 |
| 익명 FTUE 퍼널 | 설명/행동/재대결 중 실제 이탈 지점을 개인정보 없이 확인 |

## 리텐션 판단

가장 위험한 구간은 `첫 방 입장 전`, `첫 밤 행동 전`, `첫 결과 직후`다. 이번 구현은 각 구간에 하나의 명확한 다음 행동만 추가했다.

- 입장 전: 게임 방법 확인 또는 방 선택
- 첫 밤: 직업 화면에서 대상 선택
- 결과 직후: 개인 복기 확인 후 한 판 더 선택

계측 결과는 이벤트별 총량으로 다음 비율을 확인하는 데 사용한다.

- 안내 완료율: `guide_completed / guide_opened`
- 첫 판 시작 전환: `first_game_started / room_joined`
- 첫 행동 도달: `first_night_action_completed / first_game_started`
- 첫 판 완료율: `first_game_finished / first_game_started`
- 재대결 의향: `rematch_selected / first_game_finished`
- 실제 두 번째 판 시작: `second_game_started / first_game_finished`

이벤트끼리 사용자를 연결하지 않으므로 개인 단위 코호트 분석은 하지 않는다. 운영 판단은 같은 기간의 집계 비율과 플레이테스트 관찰을 함께 사용한다.

지표 전송은 게임 진행을 막지 않는 best-effort 경로다. ZEP 런타임이 요청 시작을 거절하면 이벤트 비트를 확정하지 않아 다음 관측에서 재시도한다. 로컬 검증은 payload와 요청 수락 처리까지 보장하지만 외부 수집기의 `FTUE` collection 수용 여부는 배포 후 집계 화면에서 별도로 확인해야 한다.

## 검증 범위

- 로비 접속자 수 초기값과 접속/이탈 갱신
- 게스트 참가 차단, 관전, 이름 변경 복구, 종료 후 자동 승격 차단
- 게임 시작/종료/중단/재접속의 공격 상태
- 방 중심 카메라, 게임 종료와 관전 종료 시 초기화
- 유령 채팅의 역할/진영 비노출
- 종료 정체 공개의 번호/닉네임 병기
- 개인 복기의 소유자 격리
- FTUE 이벤트 allowlist, 중복 방지, 기존 사용자/게스트 제외
- 첫 판 종료에서 재대결 선택과 두 번째 판 시작까지의 수명주기
- 결과 화면 이탈/재접속 시 중도 이탈 집계와 재대결 분모 갱신
