# 게임 중 이탈자 사망 처리 설계

## 문제

게임 중 참가자가 접속을 끊으면 좌석과 직업은 유지되고 `connected`만 `false`가 된다. 밤 행동과 투표 진행률에서는 이탈자가 제외되지만, 승패 판정은 `alive`만 세므로 이탈자가 계속 생존자로 남아 게임 종료를 늦출 수 있다.

## 결정

게임 중 이탈자는 즉시 죽이지 않는다. 현재 페이즈가 끝날 때까지 재접속을 허용하고, 페이즈 전환 시점에도 `alive && !connected`이면 이탈 사망 처리한다.

- 좌석은 삭제하지 않고 `alive=false`로 바꾼다.
- 전환 전 재접속하면 `connected=true`가 되어 사망 대상에서 빠진다.
- 사망 후 재접속하면 기존 재접속 경로를 통해 유령으로 돌아온다.
- 이미 제출한 투표와 밤 행동은 현재 페이즈 결과에 반영한다. 접속을 끊어 확정 행동을 취소하거나 결과를 되돌릴 수 없게 한다.
- 접속자가 2명 미만이면 기존 규칙대로 게임을 중단하고 대기실로 복귀한다. 이 경우 이탈 사망으로 승패를 만들지 않는다.

## 처리 순서

페이즈가 끝나면 다음 순서를 지킨다.

1. 밤 공격이나 투표 개표처럼 현재 페이즈의 고유 결과를 먼저 확정한다.
2. 아직 접속이 끊긴 생존자를 `DISCONNECT` 사인으로 사망 처리한다.
3. 모든 사망을 반영한 뒤 승패를 한 번 판정한다.
4. 승패가 나지 않았을 때만 다음 페이즈 화면을 연다.

직업 공개, 낮 토론, 개표 결과처럼 별도 정산이 없는 페이즈에서는 이탈 사망부터 처리한 뒤 승패를 판정한다.

## 코드 경계

- `Lobby.handleDisconnect`: 기존처럼 `connected=false`와 이탈 기록만 담당한다.
- `Death`: `DISCONNECT` 사인과 좌석을 보존한 이탈 사망 처리를 기존 `kill` 경로로 합친다.
- `GameFlow.advancePhase`: 현재 페이즈 정산과 다음 페이즈 시작 사이에서 이탈 사망 및 승패 판정을 실행한다.
- `WinCondition`: 변경하지 않는다. 이탈자는 경계에서 실제로 `alive=false`가 되므로 기존 생존자 계산을 그대로 쓴다.

## 안내

접속이 끊긴 순간의 기존 안내는 유지한다. 페이즈 종료 후 사망이 확정되면 방에 `이탈한 참가자가 사망했습니다`라는 별도 시스템 안내를 남긴다. 직업이나 진영은 공개하지 않으며 처형 위로 경험치도 지급하지 않는다.

## 검증

- 페이즈 종료 전 재접속하면 같은 좌석에서 생존 상태로 계속한다.
- 페이즈 종료까지 미복귀하면 좌석은 남고 `alive=false`가 된다.
- 미복귀자의 기존 투표나 밤 행동은 해당 페이즈 결과에 한 번만 반영된다.
- 이탈 사망으로 마피아 전멸 또는 마피아 수 우세가 되면 다음 화면을 열기 전에 게임이 종료된다.
- 이탈 사망 후 재접속하면 유령 화면과 유령 채팅 권한을 받는다.
- 접속자가 2명 미만이면 이탈 사망 대신 기존 게임 중단 규칙이 우선한다.

## 제외 범위

고정 초 단위 재접속 유예, 봇 대체, 이탈자 보상 차감, 좌석 제거는 이번 변경에 포함하지 않는다. 페이즈 종료까지의 유예만으로 부족하다는 실제 운영 근거가 생기면 별도로 추가한다.
