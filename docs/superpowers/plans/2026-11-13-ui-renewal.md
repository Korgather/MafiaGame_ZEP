# UI 전면 리뉴얼 — 마피아42 벤치마킹 적용 계획 (2026-11-13)

출처: `마피아42_게임플레이_UIUX_벤치마킹_보고서.docx`. 사용자가 목록 전체를 승인했다("다 좋아. 모두 진행해줘").
제약은 `docs/design/ui-redesign-brief.md`를 따른다. 그중 하나라도 어기는 설계는 받아들이지 않는다:
크기는 `layoutOf` 한 곳에서만 정한다, Jint에 `undefined`를 넘기지 않는다, `Parent`만 쓴다, 입력 뒤에는 `releaseFocus`를 부른다,
`<button>`과 `:focus-visible`을 쓴다, 색만으로 구분하지 않는다, 외부 호스트를 쓰지 않는다.

- `git stash`, `git checkout -- <file>`, `git reset`은 금지다. 커밋도 하지 않는다. `src/ui/cut.html`과 `src/ui/shared.js`에는 사용자가 커밋하지 않은 수정(webp/CDN)이 있다. 이 수정은 지우거나 되돌리지 말고 그대로 둔다. 두 파일에 무언가를 더하는 것은 괜찮다.
- 포니테일: 이미 있는 헬퍼를 다시 쓴다. 파일은 될 수 있는 한 늘리지 않는다. TODO나 스텁은 남기지 않는다.

## 단계
### A. HUD와 보드 (구조) — P0 1·2·3
1. `hud.html`을 만든다. 메시지는 `init`(phase, label, turn, timer, timeVote, role{glyph,name,team}, alive, total, coach)과 `timer`다. 보내는 쪽은 `time`(±15s)이다. 사람이 시간을 줄이거나 늘리면 로그 줄은 서버가 남긴다(C).
2. `board.html` 하나가 phase.html, vote.html, roleAction.html을 대신한다. 서버가 보내는 메시지 종류(init/timer/progress/result/allies/phrases)와 위젯이 보내는 메시지 종류(vote/select/phrase/spectate-quit/guide)는 그대로 두고, init에 `mode: "status"|"vote"|"action"`을 더한다. 옛 파일 셋은 지우고 WidgetFile도 정리한다. ±15s는 HUD로 옮긴다.
3. 보드 머리말에 지금 모드를 크게 띄운다. 예: "밤 · 능력: 치료할 사람을 고르세요", "투표 · 처형할 사람을 고르세요".
4. 선택 상태는 네 가지다. 미선택, 선택됨(다시 누르면 변경), 마감 임박(10초 이하), 실패 또는 확정(서버가 거절했거나 시간이 끝남). 하단 액션 영역에 "선택: 3번 ○○"를 다시 보여준다. 되돌릴 수 없는 능력(한 번만 쓰는 능력. 서버가 `final: true`를 실어 보낸다)에만 확인 단계를 둔다.
5. 키보드: 캔버스에 포커스가 있을 때 Parent.onKey로 숫자 1–9와 0(=10)을 받아 대상을 고른다. Esc는 변경 가능한 선택을 취소한다. 모드가 vote나 action일 때만 동작한다.
6. 메모 탭(P1 9): 좌석마다 직업 아이콘 태그(🔪 💉 🔍 🧑 ? 지우기)를 붙인다. `Parent.store.memo[gameId]`에 두고, 실패하면 try/catch로 감싼 localStorage로 물러난다. 서버로는 보내지 않는다. 보드에서는 확정 정보(ally 등, 실선 칩)와 메모(점선 "내 추정" 칩)를 다르게 그린다.
7. 재접속(P0 8)하면 HUD, 보드, 내 선택(picked)이 다시 그려져야 한다. 기존 restore 경로에 HUD 다시 열기를 더한다.

### B. 채팅 리뉴얼 — P0 4·5·6·7, P1 10·11·12, P2 16
1. 입력창 왼쪽에 청중 칩을 둔다. `ChatChannelView.audience`(예: "살아있는 모두", "마피아 팀만", "죽은 사람만")와 글리프를 함께 보여준다.
2. 채널마다 말풍선 스타일을 달리한다. `ch-<id>` 클래스, 왼쪽 띠 색, 글리프 접두를 쓴다. 색이 없어도 구분되어야 한다.
3. 사실은 SYSTEM과 EVENT 줄로, 폭 전체를 쓰는 띠로 그린다. 주장은 사람의 말로, 남은 왼쪽 내 말은 오른쪽 말풍선이다. 추정은 Parent.store의 메모 태그로, 화자 옆에 점선 "내 추정" 칩을 붙인다. 확정 직업 칩은 실선이다.
4. 행동 로그를 남긴다. 예: "N번님이 시간을 단축/연장했습니다", "N번님이 투표를 마쳤습니다"(대상은 숨긴다).
5. 입력이 막혔을 때 이유를 보여준다. 읽기 전용 탭에서 보내려 하면 placeholder에 있는 이유를 인라인 힌트로 띄운다. 쓰던 글은 `Parent.store.chatDraft`에 두어, 단계가 바뀌거나 접었다 펴도 남게 한다.
6. 스크롤 잠금을 확인하고, "새 메시지 N ↓"처럼 개수를 붙인다.
7. 사건 컷이 나올 때 같은 내용을 EVENT 카드 줄로 채팅 로그에 남긴다.
8. 화자는 번호 배지와 이름으로 보여준다.
9. 신고: 남의 USER 줄을 우클릭하거나 길게 누르면 "신고"가 나온다. 누르면 기존 `/신고` 명령어를 입력창에 채워 넣는다(답장과 같은 방식). 로그 첨부는 기존 /신고 구현이 하는 만큼만 한다.

### C. 재접속·관전·종료 — P0 8, P1 14·15, P2 18
1. 재접속하면 놓친 사건 요약을 개인 카드 줄로 보낸다(MatchRecap이나 room 기록을 다시 쓴다).
2. 죽은 사람과 관전자에게는 보드 status 모드에 사건 타임라인(`timeline: string[]`)을 보여준다.
3. 종료 화면에서는 recap을 밤(턴)별로 묶어 다시 볼 수 있게 하고, 다음 판(rematch)으로 이어지게 한다.
4. 승리 간판 연출을 CSS 애니메이션으로 넣는다. reduced-motion을 존중한다.

### D. 안내·확장 — P1 13, P2 17·19, 지표, 문서
1. 첫 판(runCount 0) 플레이어에게는 HUD나 보드에 "지금 할 일" 코치 한 줄을 띄운다. 용어에는 title 툴팁을 단다.
2. 여론조사: 낮 토론 중 살아 있는 사람이 의심 표시를 하나 할 수 있다. 구속력은 없고, 보드에 집계만 보인다. `RuleSet`에 플래그를 두고, `docs/design/balance-review.md`와 classic-mode-rules에 기록한다. 도메인 테스트를 붙인다.
3. 직업별 전적(판 수와 승)을 저장하고 프로필에 상위 3개를 보여준다.
4. 지표(FtueAnalytics): 첫 능력과 첫 투표를 마친 시점, 대상을 바꾼 횟수, 메모를 쓴 판(보드가 `memo-used`를 게임당 한 번 보낸다), 첫 판 이탈.
5. `docs/design/ui-redesign-brief.md`를 3구역 배치와 새 위젯에 맞게 고친다.

### E. 검토
code-reviewer가 따로 한 번 검토한다. 확인 항목: Jint 규칙, 채널 오배송(마피아 줄이 새지 않는가), 단계 경계에서의 입력, releaseFocus, 색 없이 구분되는가.

## 하지 않는 것
- 아바타 하이라이트: 보드에 마우스를 올렸을 때 맵의 아바타를 강조하는 기능이다. 지금 ZEP 0.16.5 API에서 확인되지 않는다.
- 연결 상태 표시: 위젯은 끊김을 알 수 없다. 재접속 요약으로 대신한다.
- 모바일 채팅과 행동을 한 iframe 바텀시트로 합치기: 기존 squeeze 구조를 그대로 두고, 보드 탭과 채팅 바로 같은 효과를 낸다.
